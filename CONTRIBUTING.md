# Contributing

Thanks for helping. This repo has a few rules that are genuinely non-negotiable, and they
are unusual enough to be worth reading before you touch anything.

New here? [`README.md`](README.md) explains what the project is.
Working on it with an agent? [`AGENTS.md`](AGENTS.md) is the source of truth, and
[`RULES.md`](RULES.md) holds the full rules.

---

## The four rules that bite

**1. Never delete anything.** To remove a file or folder, rename it — `_DELETE_ME_<name>` —
and ask a human to confirm. This applies to temp files, test fixtures, and things you created
yourself five minutes ago. `_DELETE_ME_*` paths are deliberately **not** gitignored so they
stay visible until someone signs off.

**2. Never hand-edit `data.js`.** It is generated wholesale by `scripts/build-data.js` and
overwritten on every run. If the showcase is wrong, the bug is in an `INDEX.md`, a `META.md`,
or the script. Fix the source and regenerate.

**3. Never trust a `p.md` about what a template is.** The prompt states an intent; the markup
is what shipped, and the two drift. Categories, style tags, palettes and section lists are all
read out of the real HTML and CSS. If a `p.md` and its markup disagree, file by the markup and
record the disagreement in `META.md`.

**4. Never read `dum/`.** It is private scratch space. Not listed, not grepped, not
referenced.

## Adding a template

Pick your drop zone by **shape**, not intent — anything with a `package.json` is a project:

| You have | Drop in | Handled by |
| --- | --- | --- |
| Static template: `index.html`, optionally `p.md`, optionally `styles/` `scripts/` assets | `incoming/<name>/` | `ingest-template` |
| Full React / Next.js / Astro project | `raw_make_websites/<name>/` | `import-project` |

Then run the matching skill in your agent of choice. It will:

1. Read the markup and decide the category itself.
2. File the template under `websites/<framework>/<category>/<slug>/`.
3. Write `META.md` — sections, real palette, real fonts, who it suits, who it does not.
4. Update the category `INDEX.md` (and `public-agents/INDEX.md` if the category is new).
5. Shoot a thumbnail and inject the source button.
6. Regenerate `data.js`.

Framework-by-framework guides are in `docs/`.

### If you are writing `META.md` by hand

Match an existing one exactly — they are all the same shape. The bar that matters:

> If your `META.md` could be swapped with a sibling template's and nobody would notice,
> it is wrong.

Templates in a category were often generated from near-identical prompts and are genuinely
different builds. Telling them apart is the entire value of the file.

## Scripts

```bash
node scripts/build-data.js          # regenerate data.js  (run after any shelf change)
node scripts/build-data.js --check  # report drift, write nothing — good for CI
node scripts/shoot-thumbs.js        # screenshot templates missing a thumb.webp
node scripts/shoot-thumbs.js --all  # re-shoot everything
node scripts/build-kb.js            # regenerate the kb/ registry
```

No `npm install`, ever. Everything is plain Node using `fs` and `path` only, so it runs in
any sandbox. `shoot-thumbs.js` additionally drives a locally installed Chrome or Edge over
the DevTools Protocol via Node's built-in `WebSocket` (Node 21+) — still no packages.

**`build-data.js` refuses to write when the shelf is inconsistent.** A template listed with
no folder, a folder whose `META.md` no index mentions, a category missing from
`public-agents/INDEX.md`, a declared-but-missing thumbnail — all hard errors. That is the
feature, not an obstacle: fix the source files.

## Previewing the showcase

```bash
python -m http.server 8000     # or: npx serve .
```

Serve over HTTP. Opening `index.html` as a `file://` URL will not work — the page fetches
`data.js` and same-origin assets.

## Commits

One commit per logical change. Say what changed and **why**; do not restate the diff.

**No trailers.** No `Co-Authored-By:`, no `Claude-Session:`, no session URLs, no generated
attribution of any kind. The message ends with the last line of prose.

Keep `dum/` out of unrelated commits.

---

## Pull requests

Before opening one:

- [ ] `node scripts/build-data.js --check` passes
- [ ] Every template folder you touched has a `META.md`
- [ ] Nothing is flagged `_DELETE_ME_*` without a note saying so
- [ ] Relative links in any markdown you edited resolve
- [ ] `data.js` was regenerated by the script, not by hand

Say in the PR description which templates you added or changed, and where their content came
from — see [Provenance](README.md#provenance). If a template is adapted from an existing
open-source project, name the project and its licence; that goes in the `META.md` **Origin**
row and the upstream licence keeps applying.

Do not submit templates you do not have the right to redistribute.

---

## Reporting problems

Open an issue. Useful things to include: the template slug, what you expected, what happened,
and the output of `node scripts/build-data.js --check` if the shelf is involved.
